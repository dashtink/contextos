# Shared Operating Layer

This file is not a domain — it's shared operating infrastructure every domain draws from. Domains hold what's *true*; this holds how the machinery of your actual work operates, independent of domain. Rename and adapt the sections below to your own function (this template is written for a product-marketing-shaped role, but the pattern generalizes to any job with recurring process stages, deliverable tiers, and standing meetings).

## Process Stage Definitions

Define the stages your work actually moves through, so domain notes can reference a stage name instead of re-explaining the process every time. Example shape:

| Stage | What happens |
|---|---|
| Discovery | Problem/opportunity identified, not yet scoped |
| Scoping | Requirements and stakeholders defined |
| In progress | Active build/execution |
| Review | Stakeholder or QA review before ship |
| Shipped | Live / delivered |

## Deliverable Tiering Framework

If your work produces artifacts at different levels of investment, define the tiers once here instead of re-deciding scope every time. Example shape:

| Tier | Definition | Example |
|---|---|---|
| T1 | Full bill of materials — every standard asset produced | A major launch |
| T2 | Partial — core assets only | A mid-size feature |
| T3 | Updates only to existing materials | A minor iteration |
